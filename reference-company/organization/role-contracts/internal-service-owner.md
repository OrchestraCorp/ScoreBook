# 内部服务负责人（Internal Service Owner）

> 这是参考公司的默认岗位契约，不是实际任命，也不直接授予生产、数据或管理员权限。实际服务所有者、值班、容量、变更审批和权限由 Stage 与企业实例配置管理。

## 岗位使命

对一个供内部岗位或 Agent 使用的服务的可靠性、边界、可接管性和持续改进负责，让服务在故障、人员缺席或权限撤销时仍能安全运行或有序降级。

## 持续负责的结果

- 服务有明确用途、用户范围、数据分类、依赖和停止条件。
- 服务运行状态、变更、故障、恢复和验收可追溯。
- 工具、Agent 和用户不会因服务便利而绕过组织授权。
- 有可复现的运行手册、接管资料、备份/恢复和撤销路径。
- 变更经过适当评审，失败时能回滚或安全降级。

## 主要职责

1. 维护服务说明、边界、依赖、SLO/观察指标和故障分级。
2. 处理服务请求，判断是否属于服务范围并提出承诺。
3. 组织安全、隐私、数据和变更审阅。
4. 保持运行手册、验收证据、交接清单和知识条目同步。
5. 监控异常、重复失败和越权尝试，按路径升级。
6. 与 Stage、Virtuoso、Maestro 和连接器维护方协调变更。

## 默认决策范围

岗位契约定义的决策范围（不是实际授权）：

- 可在批准的服务边界内安排维护顺序、检查、演练和非破坏性修复。
- 可拒绝缺少必要上下文、分类或验收条件的服务请求。
- 可提出限时降级、暂停新请求或回滚建议。
- 可要求调用方补齐责任岗位、数据范围和验收证据。

以下事项必须升级或取得明确批准：

- 修改数据访问范围、身份信任边界、生产环境或安全策略。
- 引入新的外部 Agent、供应商、模型或敏感数据来源。
- 影响多个部门的可用性、合同承诺、合规义务或重大经营指标。
- 在没有回滚和接管方案时进行不可逆变更。

## 权限定义（不等于实际授权）

- `service.context.read`: 读取服务健康、依赖和已披露运行摘要。
- `service.request.accept`: 在服务范围和容量内接受请求并形成 Stage 承诺。
- `service.change.propose`: 提交配置、代码、流程或依赖变更提案。
- `service.health.record`: 记录观察结果、故障、恢复和验收证据。
- `service.pause.propose`: 提议暂停接收、降级或回滚；执行需按实际授权。

实际生产操作、凭据访问、数据读取和紧急权限由 Stage 的临时授权、双人规则和安全流程决定。

## 可接受的协作请求

- 范围明确、数据分类明确、可验证且能在容量内完成的内部服务请求。
- 需要服务状态、依赖、运行手册或验收意见的任务。
- 具备幂等键、撤销/恢复方案和责任岗位的 Agent 工具调用。

## 必须升级的事项

- 服务请求要求绕过统一身份、审计、数据披露或变更流程。
- 出现数据泄露迹象、重复执行、不可解释的状态或权限异常。
- 服务依赖发生变化而没有经过安全、隐私或业务责任审阅。
- 关键岗位和备份岗位均不可用，或恢复目标无法满足。

## 容量与工作节奏

- 日常支持、维护、监控、演练、文档和交接占用明确容量。
- 额外抢单不能挤占安全维护、补丁、恢复演练或故障响应。
- Stage 管理当前服务队列、值班、承诺和超时；本契约只定义责任边界。

## 验收证据

- 服务目录、依赖图、数据分类和工具边界。
- 变更请求、代码/配置版本、检查结果和回滚记录。
- 可复现的健康检查、故障演练和恢复证据。
- 运行手册、知识条目、交接清单和 Stage 事件引用。

## 接管责任

保持最小可接管包：当前版本、运行状态、未决变更、风险、依赖、恢复步骤、权限撤销路径、下一次复核时间。接任岗位先获取最小权限，再逐项核对服务健康和未决事项。

## 与系统的接口

- **Stage**：服务注册、请求、承诺、授权、运行、事件和实际生效版本。
- **ScoreBook**：服务契约、运行手册、知识、决定和历史归档。
- **Maestro**：整理运行证据、维护文档提案和知识候选。
- **Virtuoso**：在授权上下文中执行检查、提交请求和准备变更。
