# 一、目的与适用范围

本章规定公司如何发现问题、控制风险、停止危险动作、处理失联和故障、恢复工作并将经验反馈到制度和知识。

适用于业务质量、客户事故、信息安全、合规、Agent 错误、系统故障、人员缺席、供应商失效和重大承诺冲突。

# 二、默认质量原则

质量由明确目标、可验收标准、来源可靠性、过程检查和结果回执共同构成。提交产物不等于通过验收，模型生成不等于准确。

发布任务时说明验证方法、责任人、验收人、已知限制和回滚或补救路径。高影响事项保持必要的独立复核和职责分离。

错误应尽早暴露并带有影响、范围、临时措施、负责人和下一次更新。不得因为担心评价或看板颜色而隐藏坏消息。

# 三、默认风险处理

风险记录包含来源、可能性、影响、触发条件、缓解措施、责任人、截止时间和接受或升级决定。

当事实不足时显示未知或待确认。风险模型、Agent 摘要或看板预测都是辅助信息，不能遮盖原始证据和业务判断。

发生越权、数据泄露、重复付款、错误对外发送、生产故障或客户重大影响时，先停止副作用、保留证据、通知责任人，再决定恢复或回滚。

# 四、Agent 与系统可靠性

Agent 运行设置超时、重试上限、幂等标识、取消、熔断、人工接管和回滚。外部副作用执行后取得回执或核对实际效果，避免重复发送、重复付款和重复创建。

模型、提示、工具、策略和连接器升级应有版本、验证和降级路径。无法确认兼容性时，进入只读、草稿或人工模式。

权限撤销和停止 Agent 即时生效，不等待 Git 同步。运行中的动作进入安全终止或人工接管队列。

# 五、连续性与接管

关键岗位、任务、系统和知识都应有替补或恢复方案。接管所需的上下文包、权限清单、依赖、最后核实时间和下一步必须可获得。

请假、失联、离岗或账号被撤销时，Stage 更新责任、转移允许的任务和凭据，处理排队动作并通知受影响方。

系统故障时，明确哪些工作可以暂存、哪些必须暂停、哪些可以由备用渠道处理。恢复后将离线记录与正式事实对账，不能让邮件或个人笔记长期成为影子台账。

备份覆盖数据库、附件、事件日志、Git、配置、密钥恢复材料和运行环境；恢复演练记录恢复时间、丢失范围和需要改进的控制。

# 六、监督、复盘与改进

事故关闭前说明实际影响、根因或未知、采取的措施、责任归因、客户或员工沟通、补救、证据、后续任务和复盘日期。

复盘关注系统和条件，不把所有失败归结为个人态度。故意隐瞒、滥用权限和重复违反已知边界另行处理。

Maestro 可以把复盘整理成制度或知识修订提案；任何规则变更都通过 ScoreBook 版本和相应审批，Stage 记录实际生效。

# 七、四模块承载

ScoreBook 保存质量标准、风险方法、连续性和复盘后的正式改进。Stage 保存风险、告警、事件、运行状态、责任转移和恢复回执。Maestro 整理经验并维护手册，Virtuoso 提供告警、待办、接管和回滚入口。

# 八、企业适配

企业需要配置事故等级、值班与升级、通知对象、保留期限、回滚策略、恢复目标和外部报告要求。高合规行业可以增加独立审查和证据封存。

# 九、案例

正常案例：Agent 发现外部接口重复返回结果，触发幂等保护并暂停发送，通知责任人，由人工核对后恢复，复盘结果更新连接器检查表。

例外案例：关键员工失联且任务临近客户期限。替补读取授权上下文包，Stage 临时转移任务和必要权限，旧凭据撤销，客户沟通由有权负责人确认。
