# 一、目的与适用范围

本章规定公司如何从需求理解到交付、验收、支持和问题复盘，确保对外承诺有人负责、内部协作有依据。

适用于销售、产品、项目、交付、客户成功、客服、运营和技术支持。企业按自身业务补充客户类型、交付阶段和专业系统。

# 二、默认客户责任链

每个重要客户或业务机会有责任岗位和明确的当前负责人。客户关系可以由多人维护，但对外承诺、内部交付、风险和升级路径必须有主责。

客户需求先记录原始来源、背景、确认状态和影响范围，再转化为可验收的内部任务。未经确认的推测不能直接作为客户承诺。

报价、期限、服务范围、质量承诺、数据处理和补偿等对外承诺按授权级别审批。员工 Agent 可以准备方案、摘要和邮件草稿，涉及承诺的发送由有权的人确认。

# 三、默认交付流程

需求进入后，先判断是否符合当前产品或服务范围、所需责任岗位、资源和风险。

确认后形成交付目标、版本、里程碑、验收标准、依赖、沟通节奏和客户联系人。

执行阶段持续更新承诺变化、阻塞、质量风险和客户影响。范围变化应先说明对价格、期限、资源和验收的影响，再由适当责任人批准。

提交交付物时提供版本、已知限制、验证证据和客户需要采取的动作。客户验收、内部验收和技术检查分别记录。

交付后将问题、反馈、续约机会和可复用经验写回相应任务和知识资产，不把客户沟通只留在私人邮箱或 Agent 会话。

# 四、客户数据与对外沟通边界

客户资料按数据分级处理。为了完成任务而读取的材料只进入必要的上下文，不因客户关系存在就向全公司开放。

外部发送前检查收件人、附件、引用版本、承诺内容和是否包含未获批准信息。Agent 默认生成草稿或提供发送前检查，不能自行作出未授权的法律、价格、赔偿或期限承诺。

发生投诉、事故、重大延期或数据事件时，先保护客户和组织，再按责任链升级；不要为了维持“绿色状态”延迟暴露坏消息。

# 五、责任、权限与质量

客户责任岗位负责事实核对、期望管理和升级。交付主责负责内部计划和结果。专业岗位负责其范围内的质量和风险。验收人按标准核对，不以客户满意的表述替代必要的技术或合规检查。

客户成功可以提出改进任务，但不能绕过产品、工程、财务或法务的专业责任。销售可以推动机会，但不能直接改变已承诺的交付能力。

# 六、四模块承载

ScoreBook 保存客户交付方法、质量标准、沟通模板和正式案例。Stage 保存客户对象、机会、承诺、任务、依赖、交付版本、验收和升级事件。Maestro 将经确认的案例整理成 SOP，Virtuoso 为员工和 Agent 组装客户上下文。

正式客户记录进入适当的业务系统或受限仓库；ScoreBook 只保存经过批准的通用知识、引用和脱敏案例。

# 七、企业适配

企业需要配置客户数据分类、外部承诺审批、客户分级、响应时间、交付阶段、专业系统和争议升级规则。小企业可以由同一人兼任多个责任，但仍要保留承诺和验收记录。

# 八、案例

正常案例：客户提出报表需求，客户成功记录需求，产品确认范围，工程按任务承诺交付，客户成功组织验收，最终版本和反馈写回 Stage。

例外案例：客户要求提前上线并附带赔偿承诺。销售 Agent 只能准备选项；业务、工程和法务责任人评估影响，有权人批准后才能向客户发送最终承诺。
