# 一、目的与适用范围

本章规定公司如何把使命转成可执行目标，并把人员、时间、资金、工具和 Agent 能力配置到目标上。

它适用于年度方向、季度重点、项目组合、日常服务、维护工作、风险预防和临时事件。企业采用时补充目标周期、经营指标和预算参数。

目标不是任务清单的总和。目标描述需要改变的业务结果，任务描述为结果采取的行动，证据用于判断是否发生了改变。

# 二、默认目标结构

每个重要目标应有目标说明、业务理由、责任岗位、目标周期、衡量方式、关键假设、资源需求、依赖、风险、决策期限和复核方式。

目标应尽量连接客户价值、经营结果、组织能力或风险降低中的一项或多项。只写“完成若干项工作”而没有结果意义的，不作为完整目标发布。

公司目标分为经营目标、能力目标、持续服务目标和风险目标。维护、交接、安全、合规和知识建设不因难以量化而被排除。

一个目标可以拆成多个任务，但任务必须引用目标版本。目标改变后，相关任务应显示受影响范围，不应静默改写原承诺。

# 三、默认规划与优先级

经营者确定有限数量的公司重点，说明为什么现在做、什么不做、需要哪些资源以及成功和失败的含义。

部门或岗位负责人把公司重点转为本领域承诺，并向上反馈依赖、容量和不可行条件。计划不是单向下达；未解决的资源冲突应成为可见的经营决定。

优先级按价值、紧迫性、风险、依赖、不可逆性和机会成本综合判断。Agent 可以整理候选排序，但不能仅按活动数量、消息数量或模型评分自动决定公司优先级。

目标暂停、取消或调整时，记录原因、原目标版本、已投入资源、未完成承诺、受影响人员和后续处理。

# 四、默认容量与资源规则

岗位的持续主责、客户服务、轮值、维护、评审、带教和学习应先预留容量，再开放额外任务。

任务发布前，责任岗位说明所需能力、预计投入、期限、依赖、数据范围和可用工具。若资源不足，先调整范围、期限或优先级，不默认通过加班填补。

Agent 的算力、工具调用和第三方服务额度也属于组织资源。高成本或外部副作用动作应有预算、限额和可停止条件。

抢单或认领机会用于匹配能力和兴趣，不代替岗位主责，也不使员工因不抢额外任务而无法达到岗位基本预期。

当同一资源被多个目标争用时，由目标责任人提出选项，资源负责人和受影响岗位共同确认；不能通过私下排队和隐藏承诺解决结构性冲突。

# 五、经营节奏

企业至少建立年度方向、季度重点和月度检查三个层次。具体周期可调整，但每个周期都应有目标回顾、风险检查和资源重排。

月度检查关注目标变化、阻塞、承诺偏差、容量和需要决策的问题，不进行没有证据的全员排名。

季度检查关注结果、质量、长期能力、目标取舍和下一周期资源。年度检查关注使命、业务组合、岗位责任、组织能力、治理规则和长期投资。

重要决定在周期内发生时立即记录，不等到周期结束才补写依据。

# 六、责任、边界与系统承载

经营者负责公司目标、不可接受风险和资源取舍；管理者负责领域目标、依赖协调和异常升级；岗位负责人负责可交付结果与容量承诺；员工和 Agent 在授权内执行并暴露问题。

ScoreBook 保存目标原则、规划方法、正式经营决定和复盘结论。Stage 保存当前目标、任务、承诺、资源和状态。Maestro 整理周期复盘并提出手册改进，Virtuoso 呈现目标上下文和个人待办。

目标摘要进入经营看板时遵守数据分级。未确认推断应标记为推断，不能作为经营事实发布。

# 七、企业适配

企业需要填写使命、经营领域、目标周期、指标定义、预算和资源责任人。可以改变目标节奏、审批深度和指标体系，但应说明对响应速度、透明度和风险的影响。

不建议在参考手册中写死单一行业指标或所有公司的固定目标数量。统一的是目标与责任的结构，具体内容由企业实例化。

# 八、正常与例外案例

正常案例：公司决定提升客户交付质量。客户成功岗位负责结果，工程和运营分别承担依赖，Stage 显示资源占用，季度复盘同时看客户结果、缺陷率和知识沉淀。

例外案例：经营者临时要求插入高优先级活动。提出者必须说明被挤出的工作、资源影响和截止日期；责任岗位确认后由 Stage 生成新目标或变更版本，不能仅在聊天中改变全员优先级。
