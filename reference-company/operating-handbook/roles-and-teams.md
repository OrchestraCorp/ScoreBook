# 一、目的与适用范围

本章定义岗位、部门、团队、项目和临时编组之间的关系，确保组织可以灵活组合，同时不会让责任散失。

它适用于持续岗位、兼岗、项目组、轮值、替补、外部支持和 Agent 代表的工作。企业采用时填写实际岗位、人员、汇报关系和替补安排。

部门是组织范围与协作接口，岗位是持续责任与决策范围，团队是为特定结果形成的工作编组。三者不应混为同一个权限概念。

# 二、默认岗位契约

每个岗位至少有使命、持续负责的结果、输入、输出、决策权、不能决定的事项、所需能力、数据范围、响应窗口、承诺容量、质量标准、升级对象和替补方法。

岗位契约描述责任，不等同于一张职位说明书。岗位可以由一人承担多个岗位，也可以由多人共同承担，但每项重要结果必须有明确主责。

岗位名称不自动授予系统权限。权限由角色能力、组织范围、对象关系、数据分类、任务版本和当前状态共同决定。

岗位负责人有责任维护标准、承接队列、安排资源和组织验收，即使任务尚未被具体员工认领。

# 三、默认部门骨架

参考公司保留执行与战略、财务、人与文化、产品、工程、销售与市场、运营、客户成功、法务与合规、信息技术与安全等常见职能。

企业可以合并或拆分这些部门。小公司可以由同一人兼任多个岗位，大公司可以在部门下建立团队和专业线。

部门目录描述使命、常见岗位、输入输出、跨部门接口和知识入口，不保存当前员工、实时容量和任务队列。

需要专业支持时，可以由内部服务岗位、跨部门项目组或外部供应商提供；使用外部能力不能取消公司内部的结果责任。

# 四、默认临时编组与接管

项目组围绕目标成立，明确项目主责、成员、决策范围、期限、依赖、验收人和退出条件。

跨部门组队不自动交换数据或动作权限。每位成员只承担自己岗位或已批准的临时范围，并把子交付和依赖写入共同任务。

关键岗位应有替补或接管路径。替补需要得到必要上下文、未决事项、权限清单、交付版本和最后核实时间，而不是只收到一段口头说明。

离岗、请假、失联和紧急替代时，Stage 负责当前任务和权限转移，ScoreBook 保留岗位与接管规则；凭据、个人会话和未授权的私人材料不随意转交。

# 五、责任与权限边界

业务责任岗位负责该类工作的标准、承接、资源协调和验收安排。任务主责负责本次交付与依赖。执行成员负责具体工作。验收人按事先条件判断结果，并保持必要的职责分离。

一个人可以被多个岗位或团队授权，但每次 Agent 行动必须明确代表哪个岗位、哪个任务和哪个授权上下文。

岗位负责人不能单方面改变其他岗位的承诺；跨岗位资源冲突需要共同决定或升级。管理者不能以“帮忙”为由把敏感数据交给无授权人员。

岗位外工作优先请求责任岗位；只有确有必要且不可由责任岗位及时完成时，才进入临时授权申请。

# 六、四模块承载

ScoreBook 保存岗位契约、部门章程、决策权模型和接管方法。Stage 保存实际任职、团队成员、容量、任务主责和临时编组。Maestro 维护岗位文档并根据复盘提出调整，Virtuoso 向员工展示其有效岗位和当前责任。

岗位契约变更进入 ScoreBook 版本流程；当前任职、代理、容量和替补启用由 Stage 记录。企业不得以修改岗位文档代替实时撤销权限。

# 七、企业适配

企业需要填写使命、实际岗位、人员映射、组织单元、汇报关系、专业资质和替补安排。可以采用不同的部门名称或无部门结构，但需要保留责任、接口、权限和接管信息。

岗位契约与劳动合同、绩效规则及法律义务的关系由企业另行审阅。参考手册不构成对具体员工的任职或薪酬承诺。

# 八、正常与例外案例

正常案例：一次产品改进项目由产品岗位主责，工程、客户成功和市场岗位组成临时团队；每个岗位承担明确子任务，统一验收标准在 Stage 中关联。

例外案例：项目主责突然无法工作。替补根据上下文包接管任务，Stage 更新有效责任和期限，并撤销原有执行凭据；ScoreBook 不被改写成实时人员状态。
