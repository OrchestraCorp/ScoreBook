# 一、目的与适用范围

本章规定谁可以作出什么决定、Agent 如何在授权内行动、岗位外事项如何申请、重要动作如何监督和停止。

它适用于任务承诺、客户承诺、资金、合同、数据、生产、权限、人员评价、对外沟通和紧急处置。

# 二、默认授权模型

授权不是一个永久的角色标签，而是由主体、使命、动作、对象、数据范围、组织范围、限额、期限、停止条件、验收和撤销方式组成的具体约束。

角色提供可用能力，岗位提供责任范围，任务和策略提供当前条件，对象关系和数据分类决定实际可见与可执行范围。

Agent 与员工、服务账号和第三方 Agent 都作为受授权主体处理；Agent 不能因为拥有工具凭据而绕过 Stage 的策略检查。

岗位内常规工作可以在预授权范围内自主决定。资金、合同、生产、权限、敏感数据、客户补偿、重大人员决定和不可逆外部承诺按风险要求人工批准。

# 三、风险分层与人工介入

低风险的查询、分类、摘要、提醒、格式检查和可回滚草稿可以自动执行并接受抽样审计。

授权内、可逆、范围明确的内部动作可以由 Agent 执行，但需要记录任务、输入、策略和结果。

改变承诺、跨范围共享、对外发送、修改生产、动用资金、签约、改变权限或影响个人重大权益的动作应提供人类决定和必要的双人规则。

紧急止损允许指定值班人先执行有限动作，但权限应限时、动作应可回滚、事后必须复盘并记录是否需要制度调整。

# 四、岗位外临时授权

岗位外事项默认由责任岗位处理。确有必要由原执行者代行时，申请必须说明任务版本、理由、动作、对象、数据字段、用途、期限、次数、停止条件、影响和回执位置。

有权的人确认并电子签名后，Stage 才能放行批准范围内的执行。审批人的职位本身不自动拥有全部审批权，职责分离和禁止转授事项不能被一张签名绕过。

签署绑定准确内容、版本和完整性校验。动作、对象、接收方、范围、限额或其他签署字段变化后，重新取得必要签署。

反复出现的临时例外应进入岗位、权限或制度调整评估，不能用连续特批永久改变组织结构。

# 五、决策记录

正式决定应记录问题、背景、可选方案、推荐、影响、依据、异议、责任人、生效范围、复核日期、取代关系和撤销条件。

事实、员工陈述、AI 推断、草案、批准决定和执行回执分开标记。AI 可以整理材料和提示遗漏，不能替代保留给人的判断。

决策者应看到足以作出判断的上下文和不确定性。复杂的原始过程可以按权限保留，不要求把所有内部模型推理当作审计材料。

# 六、监督与纠错

执行前重新核对当前权限、签署版本、撤销状态、限额和前置条件。执行中发生异常应暂停副作用并通知责任人。

任何人都可以按规定报告越权、错误、冲突或不安全行为。提出问题不应被视为不服从；恶意滥用和故意隐瞒另行处理。

管理者对下属 Agent 的聚合权限也受同样边界约束。汇总权限不能穿透锁仓或转化为任意原始数据读取。

# 七、四模块承载

ScoreBook 保存授权原则、审批规则、决策模板和正式决定。Stage 计算当前授权、运行检查、审批、签署、撤销和审计。Maestro 准备决策草案和变更提案，Virtuoso 展示待决问题和可执行动作。

# 八、企业适配

企业需要配置风险分类、审批人、双人规则、签署方式、紧急值班、不可转授清单和数据分级。采用前应按适用法律和行业要求复核，不把参考手册当作法律意见。

# 九、案例

正常案例：工程 Agent 申请在测试环境部署变更，系统检查任务、权限、回滚方案和批准版本后执行并回写结果。

例外案例：运营人员需要临时读取客户敏感记录处理事故，申请限定字段和期限，经数据责任人与业务责任人签署后执行，到期自动撤销并保存回执。
