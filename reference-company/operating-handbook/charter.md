# 一、目的与适用范围

本章是参考公司默认组织手册的总原则。它说明公司如何把人的判断、岗位责任、Agent 的执行能力和组织知识连接起来。

本章适用于经营目标、岗位工作、跨岗位协作、Agent 运行、知识沉淀和组织监督。企业完成适用性审阅、责任配置和内部采用后，才将本章作为自己的制度版本。

本章不预设具体行业、人员数量、部门名称或薪酬参数。企业可以合并、拆分或改名岗位与部门，但不得让关键责任失去明确承担者。

# 二、默认组织观

公司以人为责任主体，以岗位为工作边界，以 Agent 为受托执行和协作能力。

员工可以通过自己的 Agent 处理信息、拆解任务、准备方案、协调依赖和维护交付物；Agent 不能因为能调用工具而自动拥有超出授权的责任或权限。

岗位内部应当能够形成相对完整的工作闭环：理解目标、安排工作、暴露风险、交付结果、接受验收和复盘改进。

跨岗位工作优先通过责任岗位协作完成。确有必要由原执行者临时承担其他岗位工作时，必须提出具体申请，在职责、动作、内容和期限范围内取得有权人的确认和电子签名。

管理者和经营者与其他员工一样受授权、留痕、复核和纠错约束。职位高低不能替代事项所需的权限，也不能让重要动作跳过证据和责任链。

# 三、默认协作原则

主路径是“人—AI—AI—人”：人 A 设定目标和边界，Agent A 准备上下文，Agent B 检查自身岗位授权和容量，授权内完成协作，需要判断时请人 B 决定。

辅助路径是“AI—人—人—AI”：Agent 发现分歧或模糊取舍时，将问题交给相关人直接对齐；人类结论经确认后写回共同任务，再由 Agent 继续执行。

请求、提案、承诺、交付和验收分别记录。收到请求不等于接受责任；两个 Agent 达成一致不等于获得新权限。

任何重要事实都应能追溯来源，任何授权都应有范围和期限，任何不可逆动作都应有停止条件和人工责任人。

坏消息、未知状态和证据不足应及时暴露。系统不能用缺失数据生成“正常”状态，也不能因维护看板而压低风险等级。

# 四、透明度与最小知情

透明度服务于协作、经营和纠错，不等于所有人读取所有原始记录。

员工和相关岗位默认看到目标、责任人、期限、依赖、状态、风险、阻塞、验收和需要其行动的事项。

原始工作会话、个人评价、薪酬、合同金额、凭据、申诉材料和其他敏感内容按数据分类和职责范围限制查阅。

管理层可以在履行经营、审计或接管职责时查阅必要上下文；批量检索、导出和管理者 Agent 访问应记录目的、范围和结果。

保存工作记录不自动意味着可以将其用于绩效评价、全员检索、模型训练或对外披露。使用目的需要单独说明并遵守适用规则。

# 五、四个系统的承载边界

ScoreBook 保存制度、正式决策、岗位契约、经确认知识、协议和历史归档；它是规则与组织记忆的版本底座。

Stage 保存当前人员关系、任务、承诺、容量、授权、事件、审计和实际生效版本；它是热协作的运行事实源。

Maestro 读取授权上下文，整理工作结果，编辑 ScoreBook 文件，提出变更并准备提交；它不能批准自己的制度变更或自行使规则生效。

Virtuoso 为员工和员工 Agent 提供工作入口、会话、插件和执行环境；它通过受控接口操作 Stage 和其他工具。

正式代码、文档和交付物进入其对应 Git Repo。Git 合并不自动代表业务验收，ScoreBook 批准不自动代表 Stage 已加载生效。

# 六、默认组织承诺

公司应让承担结果的人能够看到完成工作所需的背景、权限和资源，也应让受到影响的人能够看到必要的承诺变化。

公司应为维护、评审、带教、风险预防和能力建设预留工作容量，不能只奖励容易计数的短期产出。

公司应持续构建可接管的上下文和可复用的组织知识，使人员变动、Agent 更换或工具故障不会让关键工作失去连续性。

企业采用本章时，应指定版本、生效范围、责任岗位、复核日期和偏离记录。偏离默认规则时，说明改变内容、原因、风险、负责人和恢复条件。

# 七、正常与例外案例

正常案例：市场岗位提出活动需求，责任岗位将其发布为有验收标准的任务；符合条件的执行者直接领取并由 Stage 原子确认，承诺形成后 Agent 协调工程和采购依赖。

例外案例：业务员工为应对客户事故，需要读取原本由安全岗位控制的日志。员工不能凭紧急性直接访问，应由责任岗位处理，或提交限时跨岗申请，完成必要签署后只取得指定字段和期限内的访问。
