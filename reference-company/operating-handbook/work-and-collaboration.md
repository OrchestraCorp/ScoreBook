# 一、目的与适用范围

本章规定工作如何进入组织、如何确定责任岗位、如何分派或认领、如何形成承诺、如何协作、交付和验收。

它适用于日常运营、客户事项、项目任务、维护、知识建设、临时事件和跨部门工作。企业采用时配置任务类别、资格规则和奖励参数。

# 二、默认工作入口

工作进入后先确认目标、背景、交付物、验收标准、期限、依赖、风险、数据范围、责任岗位和可用资源。

无法归类的事项进入待分流队列，由预先指定的兜底责任岗位处理。杂务不能因没有部门名称而无人负责。

跨岗位需求默认请求责任岗位协作。请求方可以说明业务理由和期望时间，但不能直接把对方的员工、容量或优先级当成自己的资源。

# 三、四种分配方式

定向分派适用于主责、轮值、紧急事项或需要特定资格的任务。分派仍须检查容量、权限、现有承诺和必要审批。

符合条件的通用任务可以直接领取。资格、岗位范围、容量、任务版本和风险条件满足后，Stage 原子确认领取成功，正式承诺立即形成。

重要、复杂或多人竞争的任务采用申请后匹配。申请只表示意愿，责任岗位或规则完成匹配并确认后才形成承诺。

跨岗位组队适用于多专业共同交付。各岗位分别承接子任务，组队不自动扩大数据、工具或动作权限。

岗位外临时承接必须走申请、人工确认、电子签名和临时授权，不得通过抢单或邀请进入频道绕过边界。

# 四、承诺内容与协作路径

承诺至少包含任务版本、目标、交付物、验收、期限、主责、执行成员、依赖、数据范围、允许工具、停止条件和升级对象。

收到请求不等于接受承诺。接受承诺不等于获得额外动作或内容权限。交付提交不等于验收通过。

主路径是“人—AI—AI—人”：员工设定目标，Agent 准备任务和上下文，协作 Agent 校验自身范围并处理，必要判断回到接收员工。

辅助路径是“AI—人—人—AI”：Agent 把分歧、关系协调和模糊取舍交给人直接沟通；人类结论经确认后写回任务，再由 Agent 执行后续工作。

人类界面应展示问题、选项、推荐、依据、影响和最迟决断时间，而不是要求人阅读所有内部运行日志。

# 五、工作状态与变更

任务至少区分草稿、已发布、申请中、已分派、已承诺、执行中、待验收、已接受和已关闭；阻塞、变更、取消和过期作为可追踪状态。

直接领取、分派确认和转派由 Stage 原子处理。请求带幂等标识和对象版本，旧版本不能被客户端静默覆盖。

目标、验收、关键范围、接收方、奖励规则或已签署字段发生变化时生成新版本，并重新取得必要确认。普通进度更新不改变已经签署的内容。

正式承诺后的退出需要说明原因并触发重新匹配、分派或升级。阻塞不等于失败，要记录来源、影响、责任人和下一次检查时间。

# 六、责任与权限边界

责任岗位在无人认领时仍负责调整范围、协调资源、定向分派或关闭任务。任务主责负责依赖和期限协调，不能单方面扩大他人权限。

执行者可以报告阻塞、申请变更和提交交付。验收人按照预先公布的条件验收，不能通过退回隐式增加范围。

员工 Agent 可以寻找任务、推荐候选人、准备申请和代为直接领取，但必须在员工有效委托内；必须由本人签署的动作不能由 Agent 代签。

# 七、工作量、竞争与协作

岗位主责、维护、值守、评审、带教和知识建设计入真实容量。完成岗位基本责任不应依赖额外抢单。

抢单用于发现能力、兴趣和可用容量，不按点击速度、最低报价或承诺最多加班的人自动优先。

拆单、转派和增加协作者不自动扩大原奖励池。贡献约定变化时记录差异和相关人员确认。

# 八、四模块承载

ScoreBook 保存工作分配原则、承诺模板、验收方法和例外规则。Stage 保存任务、资格、认领、容量、承诺、阻塞、交付和验收。Maestro 将已确认经验整理成 SOP 或模板，Virtuoso 提供员工与 Agent 的任务工作台。

# 九、企业适配

企业需要配置任务分类、岗位资格、直接领取条件、匹配规则、容量口径、验收责任、外部系统和任务市场开放范围。可以降低或提高人工确认深度，但不能隐藏承诺和授权变化。

# 十、案例

正常案例：内部支持任务公开发布，符合条件的工程员工直接领取，Stage 确认后形成承诺，Agent 读取允许的上下文并提交验收材料。

例外案例：销售员工发现客户急需技术操作，不能自行领取工程权限；先请求工程责任岗位，若确需本人代行，则提交限时跨岗申请并在签署后执行。
