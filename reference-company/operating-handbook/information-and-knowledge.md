# 一、目的与适用范围

本章规定信息如何分类、披露、留存、复用和沉淀为组织能力，使公司既能协作透明，又能保护个人、客户和业务敏感内容。

适用于任务上下文、工作会话、文档、代码、决策、SOP、Skill、案例、审计材料和管理看板。

# 二、默认信息分类

至少区分公开、内部、受限和高度敏感四类。企业可以增加行业分类，但必须说明每类信息可由谁在何种目的下访问、复制、发送和保留。

分类标签不能替代真实读权限。目录、摘要、搜索索引、缓存和 Agent 上下文也必须遵守相同的披露边界。

业务事实、个人陈述、AI 推断、草稿、批准决定和执行结果分开标记。AI 生成摘要不能自动成为事实或员工承诺。

# 三、四种用途分别治理

留存回答保存什么、为什么保存和保存多久。查阅回答谁可以查看原始记录。协作使用回答哪些内容可以进入其他任务、岗位或模型上下文。能力复用回答哪些内容可以加工为 SOP、Skill、模板或训练材料。

保存一段公司工作记录不自动授权全员检索、绩效评价、外部模型训练或对外披露。改变用途时重新判断目的、最小必要和访问范围。

私人事务、凭据、个人申诉和其他特殊敏感内容排除于通用采集，或进入独立受限渠道。

# 四、知识发布方法

任务过程先形成可核对案例，再由员工与岗位负责人确认事实和适用边界，之后整理为 SOP、Skill、模板或检查表，经过独立验证和版本发布。

正式知识应有标题、稳定标识、责任岗位、适用范围、来源、版本、状态、复核日期、取代关系和已知限制。

知识发布不意味着全员可读。发布清单说明读者、可执行动作和需要进一步审批的部分。

重复、过期或相互冲突的知识不静默覆盖。Maestro 提出合并、取代或保留并列版本的建议，责任人审阅后更新。

# 五、可交接上下文包

每个活跃任务维护目标与验收、任务版本、当前责任、有效承诺、已确认事实及来源、决定依据、未决问题、风险和依赖、下一步、所需权限、交付版本和最后核实时间。

上下文包服务于接管和协作，不能替代完整审计证据。原始会话、工具调用和失败记录按权限保存并可追溯。

管理者获取经营摘要时看到来源、更新时间和不确定性。批量读取、导出和管理者 Agent 访问需要记录。

# 六、四模块承载

ScoreBook 保存正式知识、信息分类、披露规则、决策和历史索引。Stage 保存当前任务上下文、访问策略、查询、审计和运行证据。Maestro 负责从已确认结果整理知识和提案，Virtuoso 通过权限过滤向员工和 Agent 提供上下文。

正式代码和文档交付进入对应 Repo；敏感业务事实保存在适当业务域，ScoreBook 仅保留受控索引和脱敏知识。

# 七、企业适配

企业需要配置分类、保存期限、角色范围、审计访问、员工查阅与纠错流程、知识发布人和外部共享规则。涉及个人信息、劳动关系和行业监管时，采用前须完成适用性复核。

# 八、案例

正常案例：一次客服事故形成脱敏案例，客服和运营负责人确认事实，Maestro 提炼处理检查表，经验证后发布给相关岗位。

例外案例：管理者要求读取全员原始 Agent 会话判断“积极性”。系统拒绝批量越权，改为提供与具体目标和任务相关的事实、承诺和结果摘要，并保留访问请求记录。
