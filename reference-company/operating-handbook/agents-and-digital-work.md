# 一、目的与适用范围

本章规定员工 Agent、公司 Agent、第三方 Agent、Maestro 和 Virtuoso 如何参与组织工作，并明确人的责任、Agent 的边界和可追溯要求。

本章适用于会话、工具调用、任务协调、文档整理、代码交付、外部沟通、知识检索和自动化运行。

# 二、默认主体模型

员工是岗位结果和重要判断的责任主体。员工 Agent 是受员工委托、由公司配置和审计的工作系统，不是员工本人的无限代理。

公司 Agent 代表公司某项稳定职能，绑定责任岗位、服务身份、运行策略、工具范围、数据范围和撤销机制。

第三方 Agent 是受控外部执行者，只接收完成当前任务所需的最小上下文和临时权限。它的输出默认是外部产物，不直接成为公司事实。

Maestro 负责 ScoreBook 的整理、提案和版本准备。Virtuoso 是员工和员工 Agent 的工作台。Stage 是任务、授权、运行、事件和实际生效版本的权威系统。

# 三、默认协作路径

主路径是“人—AI—AI—人”：人设定任务和边界，员工 Agent 组织上下文，协作 Agent 按岗位策略处理，需要判断或越界时回到人。

辅助路径是“AI—人—人—AI”：Agent 识别关系冲突、优先级取舍或敏感情境，促成人直接沟通，确认后的约定再由 Agent 落实。

Agent 可以提出请求、推荐分派、准备交付、整理文档和发现异常；不能凭自由对话授予自己或其他 Agent 新权限。

# 四、Agent 运行与工具边界

每次运行关联任务、主体、Agent 版本、模型版本、提示或策略版本、输入引用、工具调用、审批、输出、错误、重试和结果。

Agent 通过 Agent Gateway 和受控工具访问 Stage、Git、邮件或业务系统，不直接持有通用数据库管理员权限。

工具允许列表、数据范围、资源额度、超时、重试、停止条件和人工接管方式预先配置。外部文本、附件、Issue 或网页只能作为数据输入，不能通过提示注入改变权限。

Agent 操作代码、文档或知识时，应读取现状、编辑真实工作区、检查差异、运行适当验证并回读最终版本；宣称完成不等于完成。

# 五、员工体验与持续执行

Virtuoso 提供统一任务、审批、依赖、交付预览和上下文入口。员工不需要在多个系统间重复搬运相同背景，UI 与 Agent 操作同一个 Stage 对象和版本。

移动端适合发起、查看、判断和确认；长时间运行在云端继续。离线操作先保存草稿，正式认领、签署和授权以服务端确认回执为准。

员工可以查看 Agent 当前承诺、运行状态、数据访问摘要和待人工决定事项。停止或撤销 Agent 后，未完成运行进入安全处理和接管队列。

# 六、四模块承载

ScoreBook 保存 Agent 能力、责任、工具策略、数据边界和生命周期模板。Stage 保存实例、会话索引、临时授权、队列、运行审计、撤销和实际部署版本。Maestro 维护组织级 Agent 规范，Virtuoso 承载员工个人工作流。

代码、正式文档和知识发布进入对应 Git Repo；运行状态和原始过程留在 Stage 及受限证据存储，周期索引再归档到 ScoreBook。

# 七、企业适配

企业需要配置 Agent 类型、责任人、模型和工具、数据等级、人工介入条件、资源预算、停机策略、第三方接入和保留期限。可以使用不同模型或执行环境，但不能省略主体、授权和审计。

# 八、案例

正常案例：员工 Agent 读取任务和允许的工程仓，准备变更、创建分支并提交 MR；Stage 关联 commit，人工验收后再决定是否发布。

例外案例：第三方 Agent 需要客户字段生成分析。系统只发送批准字段和脱敏上下文，Agent 返回报告草稿，责任人核对来源后才写入正式知识。
