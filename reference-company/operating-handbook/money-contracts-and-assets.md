# 一、目的与适用范围

本章规定预算、采购、报销、付款、合同、供应商、设备、账号和其他组织资产如何被申请、批准、使用、核对和归档。

它适用于所有涉及资金、法律承诺、资产控制和敏感业务记录的工作。企业采用时配置金额等级、审批人和法律要求，但不在参考手册中写死额度。

# 二、默认控制原则

资金、合同和资产事项分开记录申请、审批、执行、接收、核对和关闭；同一人不应在高风险事项中独自完成全部环节。

每项申请说明目的、对象、供应商或接收方、预算来源、期限、数据范围、交付标准、风险、替代方案和取消条件。

批准只覆盖明确版本和范围。价格、数量、供应商、付款账户、合同条款、交付范围或数据处理方式变化后，重新评估并取得必要批准。

Agent 可以检索、比较、核对、生成草案和提醒截止日期。涉及签约、付款、账户变化、资产转移或对外承诺的最终动作按授权由人确认执行。

# 三、采购与费用

采购由责任岗位提出需求，资源或预算负责人判断必要性，采购或专业岗位按规则取得报价、合规检查和交付条件。

报销必须关联工作事项、实际支出、凭证和适用政策。不能通过拆分任务、改写用途或重复提交绕过审批。

付款前核对批准版本、收款对象、账户、发票或收据、交付验收和重复支付风险。异常时暂停付款并升级，不以时间压力代替核对。

# 四、合同与供应商

合同草案由业务责任人与法务或合规岗位共同维护。业务方确认目标和履约条件，专业岗位确认风险、责任、数据和终止条款。

只有有权签署的人才能代表公司作出合同承诺。Agent 生成的合同文本、摘要或差异不是签署本身。

供应商访问公司数据或系统时，授权应绑定用途、最小范围、期限、撤销和退出。供应商 Agent 视为外部执行者，不获得公司内部的通用权限。

# 五、资产与账号

设备、账号、密钥、许可证、数据集和知识资产应有责任岗位、所有权、使用范围、保管方式、复核日期和离岗处理。

凭据不进入 ScoreBook 或任务评论。密钥使用由受控服务管理，读取、轮换、撤销和异常访问留痕。

人员离岗、岗位变更或供应商结束合作时，及时撤销访问、回收资产、处理未完成任务和核对外部副作用。

# 六、四模块承载

ScoreBook 保存采购、合同、资产和职责分离原则、模板与已确认案例。Stage 保存申请、审批、授权、交付、付款状态和审计事件。Maestro 可整理条款、检查表和复盘，不能自行批准或执行资金动作。Virtuoso 提供受控申请、核对和待办入口。

原始合同、财务流水和人事资产记录放在受限业务域；ScoreBook 保存索引、适用方法和脱敏知识。

# 七、企业适配

企业需要配置风险等级、审批链、职责分离、供应商准入、资产分类、合同类型、预算周期和外部系统。允许不同业务线使用不同流程，但核心控制和审计要求必须清楚。

# 八、案例

正常案例：部门提出软件采购，预算负责人确认来源，采购收集报价，信息安全检查数据范围，责任人验收后由授权人批准付款。

例外案例：供应商要求立即更换收款账户。任何 Agent 或员工不得按邮件直接修改；先验证身份、冻结变更、关联合同和已批准信息，再由有权人按流程处理。
